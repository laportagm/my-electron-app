# Claude Code Project Memory: my-electron-app

## Project Overview

Brain Anatomy Visualizer is an Electron-based application for interactive 3D visualization of brain structures with AI assistant capabilities. The application allows users to explore detailed 3D models of various brain regions, with features for zooming, panning, and rotating the models.

**Technology Stack**:
- **Framework**: Electron (for cross-platform desktop app)
- **Frontend**: React with TailwindCSS
- **3D Rendering**: Three.js with React Three Fiber (R3F)
- **State Management**: Zustand
- **Module System**: Hybrid approach (ESM package with CommonJS for Electron main process)
- **AI Integration**: Local LLM using node-llama-cpp

**Key Capabilities**:
- Interactive 3D visualization of brain structures
- AI assistant for answering questions about brain anatomy
- Light/dark mode support
- Advanced path resolution system for asset loading
- Draco compression for 3D models

- **3D Models**
  - `public/assets/models/`: 3D GLB files of brain structures
  - `public/draco/`: Draco decoders for compressed models

- **Build Configuration**
  - `vite.config.ts`: Frontend build configuration
  - `electron-builder.yml`: Electron packaging configuration

## Style Guide

### TypeScript Standards

- **Strong Typing**: Use explicit type annotations for function parameters and return types
  ```typescript
  public async resolvePath(
    type: AssetType,
    id: string,
    options: {
      extension?: string,
      variant?: string,
      forceRefresh?: boolean,
      skipCache?: boolean
    } = {}
  ): Promise<string> {
    // Implementation
  }
  ```

- **Interfaces Over Types**: Prefer interfaces for object definitions to allow extension
  ```typescript
  interface AssetResolverOptions {
    basePath?: string;
    useFallback?: boolean;
    timeout?: number;
  }
  ```

- **Enums for Constants**: Use enums for related constants
  ```typescript
  enum ResolutionStrategy {
    STANDARD = 'standard',
    FALLBACK = 'fallback',
    FORCE_REMOTE = 'force-remote'
  }
  ```

- **Null Safety**: Use optional chaining and nullish coalescing
  ```typescript
  const result = maybeObject?.property ?? defaultValue;
  ```

### Naming Conventions

- **PascalCase**: Classes, interfaces, types, enums
  ```typescript
  class AssetPathResolver {}
  interface ConfigOptions {}
  type ModelVariant = 'high-poly' | 'low-poly';
  enum LoadingState {}
  ```

- **camelCase**: Variables, functions, methods, properties
  ```typescript
  const userSettings = {};
  function loadModel() {}
  const assetResolver = new AssetPathResolver();
  ```

- **UPPER_SNAKE_CASE**: Constants
  ```typescript
  const MAX_LOAD_ATTEMPTS = 3;
  const DEFAULT_TIMEOUT_MS = 5000;
  ```

- **Prefixes**:
  - Interface names should not be prefixed with `I`
  - Private class fields use `_` prefix
  ```typescript
  class ModelLoader {
    private _cache: Map<string, Model> = new Map();
  }
  ```

### Import/Export Patterns

- **Named Exports**: Prefer named exports for better tree-shaking
  ```typescript
  // Good
  export function parseConfig() {}
  export class ConfigManager {}
  
  // Avoid default exports when possible
  export default config; // Use sparingly
  ```

- **Import Grouping**: Group imports by source type
  ```typescript
  // Node.js built-ins
  import * as path from 'path';
  import { promises as fs } from 'fs';
  
  // Third-party dependencies
  import { app, BrowserWindow } from 'electron';
  import React, { useState, useEffect } from 'react';
  
  // Internal modules
  import { SafePath } from '../utils/pathUtils';
  import type { AssetType } from '../types';
  ```

- **Dynamic Imports**: Use for conditional module loading
  ```typescript
  const loadPathModule = async () => {
    if (isMain) {
      return await import('path');
    }
    return null;
  };
  ```

## Error Prevention Patterns

### Environment Detection

- **Process Type Detection**: Check environment before using Node.js APIs
  ```typescript
  const isMain = typeof process !== 'undefined' && 
    (typeof (process as any).type === 'undefined' || 
    (process as any).type === 'browser');
    
  const isRenderer = typeof process !== 'undefined' && 
    (process as any).type === 'renderer';
    
  const isNode = typeof process !== 'undefined' && 
    typeof process.versions !== 'undefined' && 
    typeof process.versions.node !== 'undefined';
  ```

### Safe API Access

- **Feature Detection**: Check if APIs exist before using them
  ```typescript
  const getElectronPath = () => {
    if (window?.electron?.path) {
      return window.electron.path;
    }
    return null;
  };
  ```

- **Try-Catch Wrappers**: Wrap external API calls
  ```typescript
  const safeJoin = (...parts: string[]): string => {
    try {
      return path.join(...parts);
    } catch (err) {
      console.error('Path join error:', err);
      return parts.filter(Boolean).join('/').replace(/\/+/g, '/');
    }
  };
  ```

### Fallback Implementations

- **Module Fallbacks**: Provide alternatives when modules aren't available
  ```typescript
  const getPathModule = () => {
    try {
      if (typeof require !== 'undefined') {
        return require('path');
      }
      // Fallback path implementation
      return {
        join: (...parts: string[]) => parts.filter(Boolean).join('/').replace(/\/+/g, '/'),
        resolve: (...parts: string[]) => '/' + parts.filter(Boolean).join('/'),
        // Other path functions...
      };
    } catch (err) {
      console.error('Failed to get path module:', err);
      // Return minimal fallback
      return {
        join: (...parts: string[]) => parts.filter(Boolean).join('/'),
        // Other minimal implementations...
      };
    }
  };
  ```

### Enhanced Error Logging

- **Diagnostic Context**: Include context in error messages
  ```typescript
  try {
    const result = await complexOperation();
    return result;
  } catch (err) {
    console.error(`Error in complexOperation [env=${process.env.NODE_ENV}, processType=${(process as any).type}]:`, err);
    return fallbackValue;
  }
  ```

- **Structured Error Handling**: Organize error handling by type
  ```typescript
  try {
    return await loadAsset(id);
  } catch (err) {
    if (err.code === 'ENOENT') {
      console.warn(`Asset not found: ${id}, using fallback`);
      return loadFallbackAsset(id);
    } else if (err.message.includes('timeout')) {
      console.error(`Timeout loading asset: ${id}`);
      return cacheExpiredAsset(id);
    } else {
      console.error(`Unknown error loading asset ${id}:`, err);
      return null;
    }
  }
  ```
